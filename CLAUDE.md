# Working on npd

npd generates systemd units and nginx snippets from an `npd.toml` per repo.
`README.md` is the user-facing documentation, `BACKLOG.md` is the running list
of known bugs and ideas. This file is the stuff that is easy to break and hard
to infer from any single file.

## Shape

`config.py` (parse, pure) → `render.py` (exact file text, pure) → `reconcile.py`
(diff, write, reload — the only layer that touches disk or subprocesses), driven
by `commands.py` and `cli.py`. Keep the first two pure: they are tested by
asserting the exact generated bytes.

- **Standard library only.** Python ≥3.11 (`tomllib`). Dev dependency: pytest.
- **Every subprocess goes through the `Runner` seam** so tests can record
  instead of run — *except* output a human reads (build steps, `logs`, the
  journal tail after a failed health check, the dev server). `RealRunner` sets
  `capture_output=True`, which swallows those; use `subprocess.call` directly
  there. This has been re-broken four times.
- **Status lines use `print(..., flush=True)`** — they precede subprocesses that
  write straight to the terminal, and would otherwise appear out of order.

## Invariants

- **No state file. The generated unit is the record** — the port is read back
  from `Environment="PORT=..."` and the deployed commit from `NPD_COMMIT`. That
  commit stamp is what distinguishes "nothing changed" from "the last build
  failed after pulling"; a static app answers the same question with its
  published symlink. Don't add a state file to make something easier.
- **Every generated file starts with the managed header.** A file without it is
  someone's own work: refuse, never overwrite.
- **Never delete a clone and never `git clean`** — apps keep their data there.
  Only `remove --purge`, after confirmation, deletes app data.
- **`sudo` is only ever `systemctl` and `nginx`.** Everything else runs as the
  invoking user.
- **Apply is all-or-nothing**: `nginx -t` before any reload, and a failure
  restores every file written in that run, across *both* artifact kinds.
- **New config keys must be added to `_KNOWN_KEYS`** in `config.py`, or the
  parser rejects the key it just learned about.
- **Keep unchanged apps rendering byte-identically.** A cosmetic change to the
  unit template restarts every app on the box at its next update.
- Box-specific values live in `settings.py` with env overrides. Don't hardcode a
  user, host or path anywhere else.

## Working rules

- **Tests first.** 300+ tests, `uv run pytest` from the repo root; they run
  against a temp `--root` and need no systemd. A test that passes the moment you
  write it proves nothing.
- Name tests as sentences about behaviour, and build config variants by
  `.replace()`-ing the shared fixture rather than adding another whole TOML blob.
- **A `ConfigError` says why the rule exists**, not just that it was broken.
- After a change that alters generated output, render a real unit and check it
  (`systemd-analyze verify` on the server catches what Python tests cannot).
- Record follow-ups in `BACKLOG.md`. The specs under `docs/superpowers/` are a
  historical record of the original build — don't update them per feature.
- Commit messages: `feat:`/`fix:`/`docs:` and prose explaining the behaviour
  change. Commit when asked; the user pushes.
